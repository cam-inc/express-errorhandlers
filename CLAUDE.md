# express-errorhandlers

Error handling middleware for Express.js.

## Project Structure

- `src/` — TypeScript source
  - `handler.ts` — `Handler` class (extends `Error`)
  - `middleware/error_handler.ts` — Main error handler middleware
  - `middleware/not_found.ts` — 404 handler
  - `middleware/skip_ok_hander.ts` — Skip specific paths with 200 OK
  - `views/` — Pug templates for HTML/text error responses
- `__test__/` — Jest tests
- `demo.ts` — Demo Express server
- `dist/` — Compiled output (generated by `tsc`)

## Commands

- `npm test` — Run tests (Jest)
- `npm run build` — Compile TypeScript → `dist/`
- `npm run lint` — Run ESLint + remark
- `npm run format` — Run Prettier

## Build Note

After modifying `.ts` source files, run `npx tsc` to rebuild `dist/`.
The `demo.js` file in the project root is a compiled artifact — the `request.test.ts` test imports from `../demo` and may use the compiled `.js` if it exists. Always rebuild before running tests to avoid stale compiled code.

## Security Policy

Error responses must never include sensitive information. The following must not appear in HTTP responses:

- Stack traces
- Request headers (may contain SPIFFE IDs, internal certificates, etc.)
- Internal debug data (`extraDebug`)
- Internal file paths

These are only output to server-side logs (`debug` module / `final` callback).
